Support

Raster Tech: help

Quick answers to the questions we get most.

If yours isn't here, email support@rastertech.app. Our hours are Tuesday to Sunday, noon to 8pm Eastern, when shows are running. Paying customers hear back within 4 of those hours, and beta testers within a day. If your show can't run, put SHOW DOWN in the subject and we answer right away.

Installing

Windows says "Windows protected your PC."

The beta builds aren't code-signed yet. Click More info, then Run anyway. You only do this once on each computer.

My Mac won't open the app.

The beta isn't signed by Apple yet. Drag the app onto Applications and open it. When macOS says it can't check the app, click Done (not Move to Trash), then go to System Settings → Privacy & Security and click Open Anyway. macOS asks once more: click Open Anyway again (not Move to Trash or Done), and enter your Mac password. You only do this once. (Right-click → Open only works on macOS 14.)

My antivirus flagged it.

Unsigned beta builds sometimes get flagged. Check that you downloaded it from the release page. If you're unsure, email us before allowing it.

After updating, it asks me to sign in and pick my sheet again.

That's expected from version 0.1.10 onward: the app now opens only the sheets you pick. Live monitoring pauses until you pick it, so update between shows, not during one.

After an update, Live Monitor is paused. Why?

From version 0.1.16, the first time a new version opens with a show already linked, Live Monitor starts paused, and the computer running Raster Run asks whether to resume it for your show. Choose Resume, or Not now to keep it paused until you're ready. Companion's Toggle Live Monitor button counts as an answer too, when Companion runs on the same computer.

How do I update?

Use Check for Updates in the app, or download the newest installer from the release page. It replaces the old version in place. On Windows, if the old copy won't quit, end it in Task Manager first.

Signing in

Sign-in doesn't work.

Check you picked the right show sheet in the file picker. If it still doesn't work, email us the account you're using.

It keeps asking me to sign in again.

That shouldn't happen often now. If it does, click Sign in again — your settings are kept — and let us know, since it may be a bug worth fixing.

Which Google account should I use?

The one that can open your show's tech sheet.

Audits and the dashboard

A device shows "not checked" instead of Failed.

It's on a VLAN your laptop can't reach from the port it's plugged into. The app says "not checked" rather than guessing. Plug into a port on that VLAN, or a trunk, to check it.

A device I know is working shows Failed.

Check that the sheet has its IP address, not a .local name. Many AV switches don't pass .local traffic. Then check the laptop is on the right network. One missed ping never fails a device on its own; it has to miss several in a row.

Lots of devices went red at once.

The dashboard shows a banner when that happens. It usually means the laptop lost its connection (a cable, a switch port, Wi-Fi taking over) rather than half the rig dying. Check the laptop's own connection first.

The screen says STALE.

The data is old because the app hasn't refreshed recently. Nothing you're seeing is being passed off as current. It clears on the next good update. If it doesn't, check the laptop is still on the show network.

After updating, some green devices turned red.

Version 0.1.6 fixed a Windows problem where a device that was switched off could still show green. Red now means it really didn't answer.

How do I leave a VLAN out of the show?

Put a Y in the Hide VLAN row, at the top of the IP INDEX tab, under that VLAN. Those devices are left out of the show entirely — no tile, no tally.

How do I see the dashboard on my phone?

Put the phone on the show network and open raster.local:5000 in its browser, or the laptop's IP address with :5000. From version 0.1.16, Settings → This Computer → Open on a phone or tablet lists each address with a QR code to scan. Some Android phones don't find raster.local, so use the IP address there.

My phone can't reach the dashboard (Windows laptop).

Usually it's Windows Firewall. Show networks count as Public, and Windows often only lets the app in on Private ones. From version 0.1.16, Settings → This Computer says Phones can't connect yet: click Let phones connect. On older versions, open Windows Security → Firewall & network protection → Allow an app through firewall and tick both Private and Public for Raster Run.

My phone still can't reach it.

The phone has to be on a network the laptop is plugged into or joined to. A guest Wi-Fi, mobile data, or a network on the far side of a router won't reach it. Venue guest Wi-Fi usually stops devices talking to each other on purpose, so use the show network's Wi-Fi.

Who else on the network can use my dashboard?

Anyone who can reach this computer can view it, press Audit Now and set device overrides, until you set a PIN (Settings → Set Up PIN Lock) and lock the dashboard. Switching the show, signing out and changing the PIN only ever work on the computer running Raster Run. From version 0.1.16, at a public venue, tick Phones need the PIN even to view (Settings → Dashboard Lock).

A phone says it needs the PIN, or to make the change on the other computer.

That's on purpose. If the phone shows a PIN screen, enter the dashboard PIN there. If the dashboard is locked, unlock it from a laptop or the computer running Tech Sheet (a phone shows a simpler view, with no lock button). Some changes, like switching the show, only work on the computer running Raster Run. Too many wrong PINs make only that phone wait a little before trying again.

Does Bitfocus Companion still work?

Yes. If Companion runs on a different computer, its Toggle Live Monitor button is refused, since only the computer running Raster Run can pause monitoring. With Phones need the PIN even to view on, Companion on another computer can't reach Raster Run at all: run Companion on the computer running Raster Run, or leave that setting off. Your own HTTP buttons should send JSON or no body.

On a Mac

It says port 5000 is busy.

On a Mac that's usually AirPlay Receiver. From version 0.1.16, Raster Run starts on the next free port for that launch and shows you the new address.

macOS asked about "local network" access.

Say yes. The app needs it to reach your show gear.

I'm not getting alerts.

Allow notifications for the app in System Settings → Notifications.

Your data

Where is my show data kept?

In your own Google Sheet, and nowhere else. We don't keep a copy.

Does it need the internet during a show?

No. It works on the show network. It only needs the internet to sign in and to read and write your sheet.

Does it change anything in my sheet?

It writes only your devices' Status, Last Check and Audit Details (and a MAC address, if that cell was blank), plus a list of unexpected gear on its own tab. Everything else in your sheet is read, never changed.

Where can I see the open-source software the app uses?

From version 0.1.12: Settings → Third-party notices in the app, also at /notices on the dashboard.

Raster Label

What does Raster Label run on?

Windows 10 and 11, and from version 0.1.2 Apple Silicon Macs on macOS 14 or later, as a free public beta. On a Mac, printing straight from Raster Label stays off until a printer passes its Mac test print; use Save labels and print from the folder. Download it here.

The print button says Save labels.

That printer hasn't had its test print with Raster Label yet, so it saves the label files instead. Click Open print folder and print them from there.

A row says Saved, not Printed.

Save labels writes the label files to the print folder for you to print yourself; it doesn't print. The row says Saved until Raster Label prints that label itself, then Printed. Either way, Only new since last save or print skips it next time.

Can it print cable labels?

Yes, from version 0.1.2. The Cables tab makes a label for every cable on your sheet's FLOW tab, the same label at each end. Add an optional Label column on FLOW to name what each cable is for; without one, the label shows where the cable runs.

Which labels print first?

Fronts. Device fronts are 18 mm and backs are 12 mm, so save or print the fronts, change the tape, then do the backs.

Something went wrong and I want to send you the details.

Open Settings (the gear) → Error log, then Copy or Export, and email it with the code from the message. It never includes your sign-in or passwords.

Error codes

What does the code at the end of a message mean?

Every message in Raster Run and Raster Label ends with a short code, like TS-SHEET-001 or LS-PRINT-002. What each code means, with the next step to try. Quote it when you write to us.

Is there a printed cheat sheet?

Yes. Each app has a one-page Quick Reference card with the screens, the buttons and the codes you're most likely to see: Raster Run · Raster Label.

Known limits in the beta

  • The installers aren't signed yet, so Windows and macOS warn you the first time (see Installing above). The warning is about the missing signature, not anything found in the app.
  • Raster Run's network setup needs Windows Pro, Enterprise or Education, or a Mac.
  • Raster Run on a Mac needs Apple Silicon (M1 or later) and macOS 14 or later.
  • REMOTE doesn't work on phones yet.
  • Licensing is switched off. The beta stays free, with nothing to activate.
  • Raster Label on a Mac prints straight from the app only after a printer passes its Mac test print; until then, use Save labels and print from the folder.

Still stuck?

Email support@rastertech.app with:

  • the code at the end of the message, if there was one
  • what you expected, and what happened instead
  • your version number (it's next to the name at the top of the dashboard, like v0.1.16), and whether you're on Windows or Mac
  • the error log (Settings → Error log → Export) and a screenshot if you can

If your show can't run and nothing above helped, put SHOW DOWN in the subject. It goes to the front of the queue.
